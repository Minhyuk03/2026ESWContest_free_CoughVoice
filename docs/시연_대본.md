> ## ⚠ 등록이 촬영 당일 아침으로 밀렸다 — 자막에 반영해야 한다
>
> 원안은 "등록은 촬영 전날까지"였다. 등록과 시연이 같은 세션이면 화면의 정확도가
> "목소리를 알아본 것"이 아니라 "그 몇 분간의 마이크 위치·자세를 외운 것"이기 때문이다.
> 이 프로젝트에서 좋게 나온 수치는 예외 없이 세션 내부였다.
>
> **9/2 아침에 s01·s04를 함께 등록하기로 했다.** 따라서 ④ 자막에 **"등록·촬영 같은 날"**을
> 반드시 명시하고, 발작 3개 100%를 화면 결과의 근거로 쓰지 않는다. 다만 둘을 같은 날·같은
> 조건·같은 개수(8개)로 등록하므로 **한쪽으로 기우는 편향은 없다** — 한쪽만 당일 등록본이면
> 애매한 클립이 전부 그쪽으로 쏠린다.
> 그리고 **등록한 DB를 촬영 직전에 지우면 안 된다** — "데이터 초기화" 참조.

## 0. 촬영 전 준비 (당일 최소 1시간 전)

### 네트워크 — 가장 큰 위험

집 구성(맥미니 서버 + 집 WiFi)은 **동아리방에서 동작하지 않는다.** 학교 WiFi는 AP 격리가
걸려 있는 경우가 많아 같은 망에 붙어도 기기 간 통신이 막힌다.

**촬영일 구성**: 폰 핫스팟에 맥북과 파이를 붙이고, **맥북을 서버로 쓴다.**

```bash
# 맥북 IP 확인
ipconfig getifaddr en0
```

```bash
# 맥북에서 서버 실행 (대시보드까지 함께 서빙)
# 게이트는 시연 동안 0.05로 올린다 — 근거는 아래 "게이트 임계치"
cd ~/Documents/Workspace/ChatGPT/Cough_EmbeddedSystem/dashboard && npm run build
cd ../server && COUGHID_COUGH_THRESHOLD=0.05 ~/.venvs/coughid/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

```bash
# 파이: 핫스팟 연결 + 서버 주소를 맥북 IP로 (systemd 유닛을 임시 override)
sudo nmcli device wifi connect "<핫스팟 이름>" password "<비밀번호>"
sudo systemctl edit coughid-edge     # 아래 내용 입력
```

```ini
[Service]
ExecStart=
ExecStart=/home/mh/Cough_EmbeddedSystem/monitor/.venv/bin/python main.py \
    --server http://<맥북IP>:8000 --device 0 --gain 5 --threshold 0.05 --hp-hz 80
```

```bash
sudo systemctl daemon-reload && sudo systemctl restart coughid-edge
journalctl -u coughid-edge -f      # POST 200이 찍히는지 확인
```

**촬영 며칠 전에 동아리방에서 한 번 리허설할 것.** 당일에 네트워크가 안 되면 손쓸 수 없다.

### 소음 확인

임계치 0.05는 **80Hz 하이패스를 건 뒤의 값**이다(2026-08-28 변경). 하이패스 전 0.10을 쓰던
시절에는 방의 저역 잡음만으로 검출기가 쉬지 않고 울렸는데 — 마이크가 받는 에너지의 63.7%가
50Hz 아래였다 — 지금은 같은 방에서 무음 30초 최대 RMS가 0.0015로 임계치까지 33배 여유가 있다.

동아리방에서도 조용한 상태로 로그를 1~2분 본다.

```bash
journalctl -u coughid-edge -f
```

- **아무도 소리를 안 내는데 `기침 검출!`이 계속 뜬다** → 하이패스가 안 걸렸을 가능성이 먼저다.
  기동 로그의 `threshold=`와 유닛의 `--hp-hz 80`을 확인한다. 그래도 울리면 `--threshold 0.08`
  정도까지만 올린다. **0.10 이상으로 올리지 말 것** — 기침 재현율이 72%로 떨어진다
- **기침해도 안 잡힌다** → 기침했을 때 로그에 찍히는 `peak_rms`를 보고 그보다 낮게 잡는다

### 게이트 임계치 — 시연 중에만 0.05로 올린다

운영 기본값은 `0.01`이다(실환경 69.2분 측정, 커밋 `6d9afc9`). 그런데 이 값은 시연에서
잡음을 통과시킨다. 2026-09-01 17시 세션 17건 실측:

    진짜 기침   cough_score 0.505 ~ 0.786
    잡음        cough_score 0.010 ~ 0.062

특히 0.010짜리 한 건은 화자 점수가 z −3.33으로 나와, **그게 낀 발작 창은 평균이 무너져
무조건 보류된다.** 발작 판정을 보여주는 ④가 잡음 하나에 무너진다는 뜻이다.

그래서 시연 중에는 `COUGHID_COUGH_THRESHOLD=0.05`로 띄운다. 근접 기침은 0.5 이상이라
10배 여유가 있다. **보고서·PPT의 게이트 수치는 0.01 기준이므로 섞어 쓰지 않는다** —
이것은 시연용 운용값이다.

### 데이터 초기화 — **순서를 틀리면 등록이 날아간다**

`cough_id.db`에는 이벤트 이력과 **화자 등록본이 같이 들어 있다.** 촬영 직전에 DB를 지우면
s01·s04 등록본까지 사라지고, 그 자리에서 다시 등록하면 등록과 시연이 같은 세션이 되어
수치의 의미가 없어진다.

**올바른 순서 (촬영 전날, 등록보다 먼저):**

```bash
cd ~/Documents/Workspace/ChatGPT/Cough_EmbeddedSystem/server
mv cough_id.db cough_id.db.$(date +%Y%m%d-%H%M) && rm -f audio_store/*.wav
```

서버를 재시작하면 관리자 계정과 알림 규칙이 다시 생성된다. **그다음에** 아래 "화자 등록"을
하고, 촬영은 다음 날 한다.

촬영 당일 화면만 깨끗하게 하고 싶다면 DB를 지우지 말고 **등록 이후의 이벤트만** 지운다.
아래 문장은 등록 샘플의 마지막 시각을 기준으로 삼아, **9/1 클립(시험셋)과 등록본은 남기고
그 뒤에 들어온 것만** 지운다. 날짜 문자열로 자르지 않는 이유는 `captured_at`이 UTC라
KST 오전 9시 이전이 전날로 잡히기 때문이다.

```bash
sqlite3 cough_id.db "delete from cough_events where enrolled=0 and captured_at > (select max(captured_at) from cough_events where enrolled=1); delete from alerts;"
```

**9/1에 들어온 클립은 리허설 측정이 끝나기 전에 지우면 안 된다** — 9/2 등록본에 대해
날짜가 분리된 유일한 시험셋이다("촬영 전 리허설 측정").

### 화자 등록 — **9/2 아침, s01·s04를 같은 조건으로 8개씩**

2026-09-01 기준 상태: s01은 8/27 엣지 8건으로 등록돼 있고, s04는 미등록(`sample_count=0`),
s02는 삭제했다. **9/2 아침에 s01도 새로 등록해 두 사람의 조건을 맞춘다.**

지켜야 할 것이 세 가지고, 셋 다 측정에서 나온 것이다.

1. **엣지 이벤트로 등록한다.** `collect_cough.py`(arecord) 통제 녹음을 쓰면 안 된다. 채널이
   달라서, 통제 녹음으로 등록했더니 동일인 0.419 / 타인 0.636으로 **순서가 뒤집힌** 적이 있다.
   s04의 통제 녹음 21개가 이미 있지만 **쓰지 않는다.**
   대시보드 → 화자 관리 → 등록 → 장치 앞에서 기침 → 들어온 이벤트에서 고른다
2. **두 사람 다 8개씩.** 등록 샘플이 많을수록 템플릿이 임베딩 공간 중심으로 끌려가
   "모두에게 후해지고", 애매한 클립이 전부 그쪽으로 쏠린다. 실측에서 같은 사람을 8개로
   등록하면 본인 정답률 80%, 20개로 등록하면 **65%로 떨어졌다.**
   2026-09-01에 라이브로 재확인했다 — s02(등록본 34개)를 그대로 두면 s01 기침의 3개 묶음
   10세트 중 정답 5·보류 5였는데, **s02를 8개로 다시 만들자 8/10으로 올랐다**(오답은 양쪽
   다 0). 개수 차이 하나로 절반이 보류에서 정답으로 바뀐다. 시연 로스터는 2인이어야 하므로
   s02는 결국 삭제했지만, **8 대 8** 규칙은 그대로 남는다
3. **9/1에 들어온 클립은 등록에 쓰지 않는다.** 그날 것은 시험셋이다(아래 리허설 측정).
   등록은 9/2 아침에 새로 낸 기침으로만 한다

> 게이트 점수가 낮다고 빼지 말 것. 게이트는 기침이냐 아니냐만 판단하며 품질 지표가 아니다 —
> 실제 기침이 0.06으로 찍힌 적이 있다. 다만 **0.05 미만은 등록에서 뺀다** — 9/1 실측에서
> 그 아래는 전부 잡음이었고, 그중 하나는 z −3.33으로 발작 평균을 통째로 무너뜨렸다.

### 촬영 전 리허설 측정 (등록 직후, 촬영 전)

**④에서 말할 100%는 s01 대 hwang(8/26 아카이브 화자)으로 잰 값이다. s01 대 s04는 아직 잰 적이
없다.** 두 사람이 가족처럼 성대 구조가 닮았으면 더 어렵다 — 측정상 형제자매가 최악 조건이다.
**찍기 전에 반드시 확인한다.**

> **2026-09-02 실측 결과 — 확인했고, 설정을 바꿔야 했다.** s01·s04를 각각 8개씩 당일 등록하고
> 9/1 s01 클립 22건(날짜 분리 약 19시간)으로 쟀더니 **T-norm을 켠 상태에서 50.0%**였다.
> 원인은 두 등록본의 σ 차이(0.1273 대 0.0852, 1.49배)이고, 두 방식의 답이 갈린 8건이
> 예외 없이 σ가 작은 s04 쪽이었다. **T-norm을 끄니 86.4%.** 그래서 촬영은 `COUGHID_TNORM=0`으로 진행했고,
> 마진 단위가 코사인으로 바뀌므로 `COUGHID_BOUT_MARGIN`도 0.2 → **0.01**로 함께 내렸다
> (0.2를 두면 모든 발작이 보류된다). 자세한 근거는 수치모음 ⑧-2.

등록이 당일이 됐으므로 시험셋을 따로 만들 수 없다. 대신 **2026-09-01에 들어온 s01 클립
17건이 9/2 등록본에 대해 날짜가 분리된 시험셋**이다. 등록 직후 이걸로 잰다 — 이 경로만이
세션 내부 수치가 아니다. (s04는 다른 날 클립이 없어 검증 자체가 불가능하다. 그래서 자막에
조건을 적는다.)

그다음 동작 확인으로, 두 사람이 각각 **5초 간격 3연속 세트를 3~4회씩** 낸 뒤 대시보드에서
판정을 본다. 이쪽은 같은 세션이라 **수치로 인용하면 안 되고** 파이프라인 확인용이다:

```bash
cd ~/Documents/Workspace/ChatGPT/Cough_EmbeddedSystem && ~/.venvs/coughid/bin/python tools/eval_date_split.py --event-ids <시작>-<끝>
```

- **발작 3개 묶음에서 95% 이상**이면 대본대로 간다
- 그보다 낮으면 ④의 자막 수치를 실제 값으로 바꾸고 묶음을 5개로 올린다(`COUGHID_BOUT_MIN=5`).
  그래도 안 되면 **④를 통째로 빼고** ③·⑤·⑥으로 간다. 기침 검출·알림·복구만으로도 대본은 성립한다
- 창(`COUGHID_BOUT_WINDOW_S`)을 60초에서 늘려 맞추고 싶은 유혹이 생기는데 **하지 않는다.**
  발작 정의(ERS 지침의 2초 공백)와 100% 측정 조건이 60초라, 늘리는 순간 그 수치를 인용할 수
  없고 두 사람이 한 발작으로 합쳐질 위험만 커진다. 손대야 한다면 마진이 먼저다
  (`COUGHID_BOUT_MARGIN` 0.2 → 0.1) — 9/1 실측에서 마진을 낮춰도 오답은 늘지 않고
  보류만 줄었다
- **T-norm 코호트는 손대지 않아도 된다 (2026-08-28 확인).** 코호트는 8/26 라벨 세션의
  hwang·choi 88건인데, 두 사람은 **s01·s02·s04 중 누구도 아니다**(사용자 확인).
  등록자가 코호트에 없으므로 조건을 만족한다.
  **(2026-09-02 갱신 — 코호트 구성은 문제가 없었으나 T-norm 자체를 껐다.** 등록 개수를
  8:8로 맞추자 σ 차이가 새 편향이 되어 정확도가 86.4% → 50.0%로 떨어졌다. 코호트 파일은
  지우지 않고 남겨 둔다 — 등록자가 늘어 개수를 맞추기 어려워지면 다시 켜는 선택지다.)

  다만 규칙은 기억해 둘 것 — **코호트에 등록자 본인이 들어가면 그 사람이 손해를 본다.**
  μ가 본인 점수에 끌려 올라가기 때문이다. 실제로 재현해봤다: hwang을 등록한 뒤 코호트에
  hwang을 남겨두니 hwang의 기침이 s01로 판정됐고, 빼고 다시 재니 3/3 정확해졌다.
  나중에 hwang·choi 중 누군가를 화자로 등록하게 되면 그때 재생성한다:

  ```bash
  ~/.venvs/coughid/bin/python tools/build_tnorm_cohort.py --exclude-speaker hwang
  ```

## 시나리오 설계 근거 (촬영 전에 읽을 것)

**"등록되지 않은 사람은 미등록으로 남습니다" 장면은 넣지 않는다 (2026-08-28 변경).**

근거가 없다. 등록되지 않은 제3자 40건을 재보니 **35건(87.5%)이 임계치를 넘어 등록자
이름을 달았다.** 미등록자가 등록본에서 얻는 우위가 등록자 본인이 얻는 우위보다 오히려
컸다. 마진 보류도 막지 못한다(발작 묶음에서 보류율 0.0%). **외부인을 데려와 "미등록으로
나옵니다"를 보여주면 카메라 앞에서 이름이 붙을 확률이 87%다.**

**대신 보여줄 것: 등록된 2인 중 누구인지를, 발작 단위로 판정하는 장면.** 이것은 측정으로
뒷받침된다 — 등록일과 시험일이 다른(약 15시간) 조건에서 **발작 3개 이상 묶으면 정확도 100%**
(기침 1개는 89.7%). 기침 1~2개만으로는 판정하지 않고 화면에 "판정 중"으로 남기며,
이것도 실제 동작이다(`core/bout.py`, 60초 창·최소 3개).

2~3명이 앉아 있는 구도는 유지하되 **전원이 등록된 상태**로 찍는다. 미등록자를 등장시키지
않는다. 서술은 "누구인지 맞힌다"가 아니라 **"등록된 거주자 중 누구인지를, 한 번의 기침이
아니라 발작 단위로 고른다"** 로 한다.

## 대본

### ① 문제 제기 (0:00~0:20)

> 화면: 동아리방 전경, 책상 가운데 라즈베리파이

혼자 사는 어르신이나 아기가 있는 집에서 기침이 언제 얼마나 늘고 있는지는
건강 상태를 살피는 단서입니다. 그런데 기존 제품은 손목에 차거나 가슴에 붙여야 합니다.
**매일 착용을 요구하는 순간, 정작 필요한 사람에게는 쓰이지 않습니다.**

### ② 시스템 소개 (0:20~0:45)

> 화면: 파이 클로즈업 → 대시보드

저희는 방에 놓아두기만 하면 되는 형태로 만들었습니다.
라즈베리파이와 마이크 하나. **착용도, 조작도, 카메라도 없습니다.**

마이크가 소리를 감지하면 서버가 기침인지 판정하고, **등록된 거주자 중 누구인지**를
가린 뒤, 기침이 반복되면 보호자에게 알립니다.

### ③ 기침 검출 (0:45~1:45) — **핵심**

> 화면: 대시보드를 띄운 노트북 + 사람들이 앉은 모습을 한 프레임에

**(s01이 기침 1회)**

3초 안에 대시보드에 나타납니다.

> 화면: 이벤트 항목 클로즈업 (시각, 화자, 유사도)

**(박수 3회)**

박수는 올라오지 않습니다. 파이는 소리를 감지했지만, 서버가 기침이 아니라고 판정해
기록하지 않습니다.

> 화면: 파이 터미널 로그 — `기침 검출!` 은 찍히는데 대시보드에는 안 나타남

**(대화 몇 마디)**

말소리도 마찬가지입니다.

> 자막: 통제 조건 검출률 98% · TV 켠 거실 20분 연속 녹음에서 오탐 0회

### ④ 화자 확인 (1:45~2:40)

> 화면: 화자 관리 화면 — 등록된 두 사람(s01 · s04)

이 집에는 **두 사람이 등록되어 있습니다.**

**(s01이 기침 1회)**

> 화면: 이벤트는 올라오지만 이름 자리가 **"미판정"**인 것

기침 하나로는 이름을 붙이지 않습니다. 한 번의 기침만으로 고르면 정확도가 89.7%입니다.
**열 번에 한 번은 틀린 이름이 기록에 남는다**는 뜻입니다.

**(s01이 이어서 2~3회 더 기침 — 5초 간격)**

> 화면: 세 번째 기침에서 **앞선 기침들까지 한꺼번에** s01 이름이 붙는 것

연속된 기침을 하나의 발작으로 묶으면 **100%**가 됩니다. 마이크와의 각도, 그때의 자세 같은
클립 하나하나의 운이 서로 상쇄되기 때문입니다. 60초 안에 세 번 이상 모이면 판정합니다.

**(⚠ 여기서 60초 이상 쉰다 — 아래 촬영 메모 참조)**

**(s04가 3회 기침 — 5초 간격)**

> 화면: s04 이름이 붙는 것

> 자막: 등록 2인 중 택1 · 발작 3개 이상 · **s01·s04 모두 촬영 당일 등록**
> 자막: "발작 3개 100%"는 등록 8/27 / 시험 8/28로 **날짜를 분리해** 따로 잰 값입니다
>       (이 영상의 장면과는 다른 조건입니다)
> 자막: 기침 1개 단위로는 89.7%입니다
> 자막: 등록되지 않은 사람을 가려내는 기능은 **없습니다**
>
> **⚠ 후반 작업에서 반드시 넣을 자막 (2026-09-02 추가)**
> 자막: 이 영상은 **T-norm을 적용하지 않은 구성**입니다. 등록 개수를 8개씩 맞추면
>       T-norm이 오히려 정확도를 떨어뜨리는 것을 촬영 당일 측정했습니다 (86.4% → 50.0%)
> 자막: s01·s04 2인 조건에서 **기침 1개 단위 86.4%** (9/1 클립 22건, 날짜 분리 약 19시간)
>       — s04 방향은 다른 날 클립이 없어 측정하지 못했습니다

**틀린 이름을 붙이는 것보다 판정을 미루는 편이 낫다**고 판단했습니다.
잘못된 이름은 기록을 오염시키지만, 보류는 그렇지 않기 때문입니다.

> **촬영 메모 — 두 사람 사이를 반드시 60초 이상 띄운다.** 발작 묶음은 **장치 기준 60초 창**이라
> 누가 냈는지를 보지 않는다. s04가 s01의 마지막 기침 후 60초 안에 기침하면 **둘이 한 발작으로
> 합쳐져** 다섯~여섯 개 전부가 한 사람 이름을 받고, 앞서 올바르게 붙은 s01 이름까지 덮어쓴다.
> 카메라 앞에서 이게 나면 그대로 남는다. **s01 파트가 끝나면 화면을 한 번 훑는 컷을 넣어
> 자연스럽게 60초를 벌고**, 진행자가 시계를 보고 큐를 준다.
> (가정집에서는 한 발작 = 한 사람이라는 가정이 대체로 맞지만, 시연은 인위적인 상황이다.)

> **말하지 말 것**: "등록되지 않은 사람은 걸러집니다." 측정 결과 외부인 40건 중 35건(87.5%)이
> 등록자 이름을 달았다. 이 시스템이 답할 수 있는 것은 **"등록된 둘 중 누구인가"까지**다.

### ⑤ 이상 징후 알림 (2:40~3:20)

> 화면: 알림 규칙 카드 — "기침 ≥ 3회 / 5분"

**(s01이 5초 간격으로 3회 기침)**

> 화면: 세 번째 기침 직후 알림이 뜨는 것

기준을 넘으면 알림이 생성됩니다.
같은 알림이 반복해서 쌓이지 않도록 재알림은 일정 시간 억제합니다.

> 화면: 알림 문구 클로즈업 — "301호 s01 · 최근 5분 기침 3회. 확인이 필요합니다."

> 촬영 메모: ④에서 이미 s01이 3~4회 기침했으므로 5분 창에 그것이 남아 있다. ④와 ⑤ 사이를
> 5분 이상 띄우거나, ⑤ 직전에 규칙 창을 리셋(규칙 저장 다시 누르기)한다. 안 그러면 ⑤에서
> 기침을 시작하자마자 알림이 떠 "3회를 세는 것"이 화면에 안 보인다.

의료기기가 아니므로 **진단하지 않습니다.** "확인이 필요합니다" 수준의 기록 보조입니다.

### ⑥ 네트워크 끊김 복구 (3:20~3:55)

> 화면: 서버를 종료

서버가 꺼진 상태에서 기침하면

**(기침 2~3회)**

파이가 디스크에 저장해둡니다.

> 화면: 서버 재시작

서버가 돌아오면 밀린 이벤트가 자동으로 전송됩니다.

> 화면: 대시보드에 한꺼번에 나타나는 것

가정에서는 공유기 재부팅이나 일시적 끊김이 흔합니다. 그 사이의 기록을 잃지 않습니다.

### ⑦ 마무리 (3:55~4:25)

> 화면: 시스템 구성도

정리하면 — 방에 놓는 마이크 하나로, 착용 없이 기침을 기록하고 이상 징후를 알립니다.

**한계도 말씀드립니다.** 여러 사람 중 누구인지 구분하는 정확도는 아직 64%이고,
특히 **가족처럼 목소리가 닮은 경우 더 어렵습니다.** 그래서 확신이 없을 때는
이름을 붙이지 않도록 설계했습니다.

기침 검출 자체는 사전학습 모델과 자체 측정으로 뒷받침했고,
모든 임계치는 감이 아니라 측정 곡선으로 정했습니다.

## 촬영 팁

- **한 프레임에 사람과 화면을 같이** 담으면 인과가 분명해진다. 화면만 찍으면 조작으로 보인다
- 기침은 **5초 간격으로 3번 연속** 낸다. 쿨다운이 2초라 더 붙이면 하나로 셈되고, 너무 띄우면
  발작(60초 창·3개 이상)이 아예 만들어지지 않는다. 2026-09-01 세션이 그랬다 — 간격이
  55~370초라 **17건 전부 미판정**이었고, 게이트·창·최소개수·마진을 72가지 조합으로 바꿔봐도
  60초 창에서는 하나도 붙지 않았다. **간격이 어떤 파라미터보다 크게 작용한다**
- **실패해도 다시 찍으면 된다.** 다만 성공한 장면만 이어붙여 "항상 된다"처럼 보이게 하지 말 것.
  ③에서 한 번 놓치는 장면이 있어도 그대로 두는 편이 오히려 신뢰를 준다
- 파이 터미널 로그를 한 번은 보여준다. 내부 동작이 보이면 설득력이 다르다
- 자막으로 수치를 넣되 **조건을 함께** 적는다 ("통제 조건 60개 기준" 등)
