# 시연 동영상 대본

> 촬영 2026-09-01 · 목표 3~5분 · 제출 필수 항목(유튜브 링크)
> 장소: 동아리방, 가운데 책상에 파이 배치, 2~3명이 서로 다른 방향에 착석

---

## 0. 촬영 전 준비 (당일 최소 1시간 전)

### 네트워크 — 가장 큰 위험

집 구성(맥미니 서버 + 집 WiFi)은 **동아리방에서 동작하지 않는다.** 학교 WiFi는 AP 격리가
걸려 있는 경우가 많아 같은 망에 붙어도 기기 간 통신이 막힌다.

**촬영일 구성**: 폰 핫스팟에 맥북과 파이를 붙이고, **맥북을 서버로 쓴다.**

```bash
# 맥북 IP 확인
ipconfig getifaddr en0
```

```bash
# 맥북에서 서버 실행 (대시보드까지 함께 서빙)
cd ~/Documents/Workspace/ChatGPT/Cough_EmbeddedSystem/dashboard && npm run build
cd ../server && ~/.venvs/coughid/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

```bash
# 파이: 핫스팟 연결 + 서버 주소를 맥북 IP로 (systemd 유닛을 임시 override)
sudo nmcli device wifi connect "<핫스팟 이름>" password "<비밀번호>"
sudo systemctl edit coughid-edge     # 아래 내용 입력
```

```ini
[Service]
ExecStart=
ExecStart=/home/mh/Cough_EmbeddedSystem/monitor/.venv/bin/python main.py \
    --server http://<맥북IP>:8000 --device 0 --gain 5 --threshold 0.10
```

```bash
sudo systemctl daemon-reload && sudo systemctl restart coughid-edge
journalctl -u coughid-edge -f      # POST 200이 찍히는지 확인
```

**촬영 며칠 전에 동아리방에서 한 번 리허설할 것.** 당일에 네트워크가 안 되면 손쓸 수 없다.

### 소음 임계치 재확인

임계치 0.10은 집 소음 바닥(0.082~0.114) 기준이다. 동아리방이 더 시끄러우면 검출기가
쉬지 않고 울린다. 조용히 있는 상태에서 로그를 보고 판단한다.

```bash
journalctl -u coughid-edge -f
```

아무도 소리를 안 내는데 `기침 검출!`이 계속 뜨면 `--threshold 0.15` 또는 `0.20`으로 올린다.
반대로 기침해도 안 잡히면 낮춘다. **기침했을 때 찍히는 `peak_rms` 값을 보고 그 아래로 잡는다.**

### 데이터 초기화

깨끗한 화면으로 시작하려면 촬영 직전에:

```bash
cd ~/Documents/Workspace/ChatGPT/Cough_EmbeddedSystem/server
mv cough_id.db cough_id.db.$(date +%H%M) && rm -f audio_store/*.wav
```

서버를 재시작하면 관리자 계정과 알림 규칙 3종이 다시 생성된다.

### 화자 등록 (촬영 직전)

**주 사용자 1명만 등록한다.** 이유는 아래 "시나리오 설계 근거" 참조.

대시보드 → 화자 관리 → 신규 등록 → 장치 앞에서 기침 8~10회 → 목록에서 선택 → 완료.

### 알림 규칙 조정

기본값 "1시간 10회"는 시연에 너무 길다. 알림 센터 → `+ 규칙 추가`:
- 이름 `시연`, 횟수 `3`, 시간 `5`분

## 시나리오 설계 근거 (촬영 전에 읽을 것)

**여러 명이 번갈아 기침하며 "누구인지 맞히는" 장면은 넣지 않는다.**

측정된 다자 식별 정확도가 **64%** 다. 셋 중 하나는 틀린다. 카메라 앞에서 틀리면
그 장면이 그대로 남고, 심사에서 신뢰를 크게 잃는다.

대신 **"등록된 거주자인지 확인하고, 확신이 없으면 미등록으로 남긴다"** 는 실제 동작을
보여준다. 이건 측정으로 뒷받침된다(임계치 0.40에서 정밀도 91%).

2~3명이 앉아 있는 구도 자체는 유지한다 — **다인 공간에서 동작한다**는 것을 보여주되,
"누구인지 맞힌다"가 아니라 **"등록자만 걸러낸다"** 로 서술한다.

## 대본

### ① 문제 제기 (0:00~0:20)

> 화면: 동아리방 전경, 책상 가운데 라즈베리파이

혼자 사는 어르신이나 아기가 있는 집에서 기침이 언제 얼마나 늘고 있는지는
건강 상태를 살피는 단서입니다. 그런데 기존 제품은 손목에 차거나 가슴에 붙여야 합니다.
**매일 착용을 요구하는 순간, 정작 필요한 사람에게는 쓰이지 않습니다.**

### ② 시스템 소개 (0:20~0:45)

> 화면: 파이 클로즈업 → 대시보드

저희는 방에 놓아두기만 하면 되는 형태로 만들었습니다.
라즈베리파이와 마이크 하나. **착용도, 조작도, 카메라도 없습니다.**

마이크가 소리를 감지하면 서버가 기침인지 판정하고, 등록된 거주자인지 확인한 뒤,
기침이 반복되면 보호자에게 알립니다.

### ③ 기침 검출 (0:45~1:45) — **핵심**

> 화면: 대시보드를 띄운 노트북 + 사람들이 앉은 모습을 한 프레임에

**(A씨가 기침 1회)**

3초 안에 대시보드에 나타납니다.

> 화면: 이벤트 항목 클로즈업 (시각, 화자, 유사도)

**(박수 3회)**

박수는 올라오지 않습니다. 파이는 소리를 감지했지만, 서버가 기침이 아니라고 판정해
기록하지 않습니다.

> 화면: 파이 터미널 로그 — `기침 검출!` 은 찍히는데 대시보드에는 안 나타남

**(대화 몇 마디)**

말소리도 마찬가지입니다.

> 자막: 통제 조건 검출률 98% · TV 켠 거실 20분 연속 녹음에서 오탐 0회

### ④ 화자 확인 (1:45~2:30)

> 화면: 화자 관리 화면 → 등록된 A씨

A씨만 등록되어 있습니다.

**(A씨가 기침 3~4회)**

> 화면: 이벤트에 A씨 이름이 붙는 것

**(B씨, C씨가 각각 기침)**

등록되지 않은 사람의 기침은 **미등록으로 남습니다.**

> 자막: 화자 식별은 통제 녹음 EER 36.4% · 실사용 EER 46.3%로 실용 수준이 아닙니다
> 자막: 백본을 WavLM으로 바꿔 38.0%까지 좁혔으나 운용 가능한 수준은 아닙니다
> 자막: 한계를 감추지 않고 측정해 밝힙니다 — 이 시연에서 이름 표시는 참고용입니다

**틀린 이름을 붙이는 것보다 모른다고 하는 편이 낫다**고 판단했습니다.
잘못된 이름은 기록을 오염시키지만, 미등록은 그렇지 않기 때문입니다.

### ⑤ 이상 징후 알림 (2:30~3:15)

> 화면: 알림 규칙 카드 — "기침 ≥ 3회 / 5분"

**(A씨가 5초 간격으로 3회 기침)**

> 화면: 세 번째 기침 직후 알림이 뜨는 것

기준을 넘으면 알림이 생성됩니다.
같은 알림이 반복해서 쌓이지 않도록 재알림은 일정 시간 억제합니다.

> 화면: 알림 문구 클로즈업 — "301호 A · 최근 5분 기침 3회. 확인이 필요합니다."

의료기기가 아니므로 **진단하지 않습니다.** "확인이 필요합니다" 수준의 기록 보조입니다.

### ⑥ 네트워크 끊김 복구 (3:15~3:50)

> 화면: 서버를 종료

서버가 꺼진 상태에서 기침하면

**(기침 2~3회)**

> 화면: 파이 로그 — `전송 실패` → `큐 적재`

파이가 디스크에 저장해둡니다.

> 화면: 서버 재시작

서버가 돌아오면 밀린 이벤트가 자동으로 전송됩니다.

> 화면: 대시보드에 한꺼번에 나타나는 것

가정에서는 공유기 재부팅이나 일시적 끊김이 흔합니다. 그 사이의 기록을 잃지 않습니다.

### ⑦ 마무리 (3:50~4:20)

> 화면: 시스템 구성도

정리하면 — 방에 놓는 마이크 하나로, 착용 없이 기침을 기록하고 이상 징후를 알립니다.

**한계도 말씀드립니다.** 여러 사람 중 누구인지 구분하는 정확도는 아직 64%이고,
특히 **가족처럼 목소리가 닮은 경우 더 어렵습니다.** 그래서 확신이 없을 때는
이름을 붙이지 않도록 설계했습니다.

기침 검출 자체는 사전학습 모델과 자체 측정으로 뒷받침했고,
모든 임계치는 감이 아니라 측정 곡선으로 정했습니다.

## 촬영 팁

- **한 프레임에 사람과 화면을 같이** 담으면 인과가 분명해진다. 화면만 찍으면 조작으로 보인다
- 기침은 **5초 이상 간격**을 둔다. 검출기 쿨다운이 2초라 너무 붙으면 하나로 셈된다
- **실패해도 다시 찍으면 된다.** 다만 성공한 장면만 이어붙여 "항상 된다"처럼 보이게 하지 말 것.
  ③에서 한 번 놓치는 장면이 있어도 그대로 두는 편이 오히려 신뢰를 준다
- 파이 터미널 로그를 한 번은 보여준다. 내부 동작이 보이면 설득력이 다르다
- 자막으로 수치를 넣되 **조건을 함께** 적는다 ("통제 조건 60개 기준" 등)

## 하지 말 것

- ❌ "누가 기침했는지 알아냅니다" — 64%다. 단정하면 검증에서 무너진다
- ❌ 외부인을 데려와 "미등록으로 나옵니다" 시연 — 진짜 외부인 표본이 부족하다
- ❌ 여러 명이 번갈아 기침하며 이름을 맞히는 장면
- ❌ 실패 장면만 잘라내고 성공만 이어붙이기
