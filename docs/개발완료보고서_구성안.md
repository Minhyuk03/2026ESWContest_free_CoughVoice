# 1. 개발 개요 (3P)

## 작품명
기침 소리 기반 화자 식별·이상 징후 알림 시스템 (가칭)

## 개발 배경
혼자 사는 고령자와 아기가 있는 가정에서 기침 빈도 변화는 건강 상태를 살피는 단서다. 그러나 기존 기침 모니터링 제품은 **손목에 차거나 가슴에 붙여야** 한다. 매일 착용을 요구하는 순간 고령자에게는 쓰이지 않는다.

## 동기
착용도 조작도 없이, 방에 놓아두기만 하면 되는 형태로 만들 수 있는가. 그리고 여러 사람이 사는 공간에서 **누구의 기침인지**까지 구분할 수 있는가.

## 목표
1. 생활 소음 환경에서 기침만 선별 검출
2. 기침 빈도 추적 및 규칙 기반 이상 징후 알림
3. 등록된 거주자 본인 확인 (마이크 하나, 레이더 없이)

## 필요성
- 의료기기가 아닌 **기록 보조 장치**로서 진단하지 않는다
- 무착용·무조작이라 인지·거동에 부담이 있는 사용자도 쓸 수 있다
- 1인 가구 증가에 따른 원격 돌봄 수요

## 필수 링크
- 소스코드: `https://github.com/Minhyuk03/Cough_EmbeddedSystem`
- 시연 동영상: **미확보 — 촬영·업로드 필요**

# 4. 개발 중 발생한 장애요인과 해결방안 (4+5+6 합산 5P)

**이 항목이 우리 강점이다.** 전부 실기에서 드러난 문제이고 원인·해결·검증이 남아 있다.

| # | 장애요인 | 원인 | 해결 |
|---|---|---|---|
| 1 | 녹음 peak가 항상 90~100%로 클리핑 오탐 | I2S 코덱이 장치 오픈 직후 0~3ms 팝 트랜지언트 발생 | 여유분 캡처 후 앞부분 0.1초 트림 |
| 2 | 마이크 오디오 유실 (`input overflow`) | 전송이 **오디오 콜백 안에서 동기 실행** | 큐 적재 후 워커 스레드 전송 |
| 3 | 기침 처리 중 서버 전체 정지 | async 핸들러에서 블로킹 CPU 추론 → 이벤트 루프 차단 | `run_in_threadpool` 분리 |
| 4 | 짧은 클립에서 서버 500 | PANNs 최소 입력 길이 미달 | 1초 미만 제로패딩 |
| 5 | 실환경 오탐 시간당 201회 | 조용한 방 20개로 임계치 결정 (과소평가) | 연속 녹음 곡선으로 재결정 |
| 6 | 화자 식별이 우연 수준으로 측정됨 | **라벨 오류** — 외부인 `x01`이 사실 등록자와 동일인 | 라벨 정정 후 재계산 |
| 7 | 수집 파일 덮어쓰기 | 재실행 시 인덱스가 001부터 재시작 | 기존 최대 번호 다음부터 부여 |
| 8 | 브라우저만 서버 접속 실패 | VS Code가 `127.0.0.1:8000` 선점 | LAN IP로 지정 |

**서술 방향**: 5번과 6번은 "측정 자체를 의심해야 한다"는 교훈으로 묶어 쓰면 강하다. 통제 샘플로 정한 임계치가 실환경에서 200배 틀렸고, 라벨 하나가 결론을 뒤집었다.

# 5. 개발 결과물의 차별성 (4와 합산)

## 폼팩터
| 제품 | 형태 |
|---|---|
| Hyfe | 손목 착용 / 스마트폰 앱 |
| Strados Labs | 흉부 부착 센서 |
| US 11,627,890 특허 | 레이더 + 오디오 |
| **본 시스템** | **방에 놓는 마이크 1개** |

무착용·무조작·비접촉. 레이더 없이 기침 음색만으로 화자를 다룬다.

## 정량 성능 (조건 명시 필수)
| 지표 | 값 | 조건 |
|---|---|---|
| 기침 검출률 | 98% | 통제 샘플 60개 |
| 실환경 검출 | 3/3 | TV 켠 거실 20분 |
| 오탐 | 0회/20분 | 95% 상한 9회/시간 |
| 소음 강건성 | 85~87% | SNR −5dB |
| 본인 확인 EER (통제 녹음) | 36.4% | 동일인 220 / 타인 340 |
| 본인 확인 EER (실사용) | 46.3% | 동일인 800 / 타인 1600 |
| 본인 확인 정밀도 | 50.8% | 임계치 0.40, 통제 녹음 |

## 방법론적 차별성
사전학습 ECAPA를 기침에 그대로 쓰면 동작하지 않음을 측정으로 보였다(EER 40.9%). 공개 데이터셋(Coswara, CC BY 4.0)으로 투영층만 학습해 36.4%까지 낮췄으나(GPU 없이 CPU만으로 수행), **이 역시 실용 수준이 아니다.**

차별성은 성능 수치가 아니라 **한계를 규명한 방식**에 둔다. 엣지가 평소대로 도는 상태에서 라벨을 붙여 실사용 EER을 재는 도구(`tools/label_session.py` · `tools/eval_label_session.py`)를 만들고, 통제 녹음 36.4%가 실사용에서 46.3%로 무너지는 것과 그 원인(화자 정체성이 아니라 녹음 블록별 환경을 학습)을 유사도 분해로 보였다. 통제 조건 수치만 제시하는 관행이 왜 위험한지를 자체 측정으로 드러낸 것이 이 프로젝트의 기여다.

# 6. 파급력 및 기대효과 (4와 합산)

- **시장**: 1인 가구·고령 가구 증가, 원격 돌봄 수요
- **활용**: 가정 → 재택 간병 → (규제 검토 후) 1~2인 병실
- **판매가치**: 라즈베리파이급 단일 장치, 착용 소모품 없음
- **발전 가능성**: 엣지 2차 판정기 탑재 시 서버 없이 독립 동작 가능
